# Attack Chain Analysis

## Chain 1: Cross-Tenant Data Exfiltration via API Pivot
- Sequence: F-03 → F-10 → F-01
- Path: An attacker first compromises a long-lived, broadly scoped hospital integration token (F-03). Because this token's excessive scope allows it to invoke various functions across tenants, the attacker utilizes it to reach the internal analytics service, confirming that the broad token can traverse this application path. Bypassing standard gateway restrictions, the attacker manipulates the `X-Lab-ID` header directly in the analytics request (F-10) to harvest valid aggregate data containing patient and diagnostic result identifiers from other laboratory tenants. Finally, the attacker feeds these harvested cross-tenant identifiers into the vulnerable Results API (F-01), exploiting the lack of tenant-level authorization checks at the data-access layer to successfully download the actual diagnostic records.
- Consolidated impact: In isolation, F-01 requires an attacker to blindly guess valid identifiers, F-10 only exposes aggregate metrics, and F-03 provides API access but not direct patient files. Chained together, the attacker weaponizes F-03 as a network pivot and F-10 as a precise identifier oracle, culminating in the systemic mass exfiltration of very high-criticality diagnostic health records (F-01). This compounded breach directly violates RGPD mandates and critically threatens MediPath's upcoming HDS certification renewal.

## Chain 2: Internal Support Pivot to Mass Export
- Sequence: F-02 → F-06
- Path: A malicious or compromised laboratory operator injects a targeted XSS payload into a laboratory support case note (F-02). When a Support Operations analyst—who requires cross-tenant visibility to perform their duties—opens the ticket, the active content executes seamlessly within their authenticated internal session. The payload leverages this high-privilege operational context to silently query the export service on behalf of the analyst, harvesting long-expired but still cryptographically valid bulk diagnostic export links (F-06) without triggering secondary authentication.
- Consolidated impact: This chain perfectly illustrates the hidden danger of medium-severity flaws. Individually, F-02 is a standard client-side risk limited by managed workstations, and F-06 is a retention policy violation. Chained together, they allow a low-privilege external user to pivot entirely through a trusted internal support session. This completely bypasses MFA and endpoint compensating controls, escalating to the massive unauthorized retrieval of regulated health data via stale export links, an impact that far exceeds the base score of either individual vulnerability.
